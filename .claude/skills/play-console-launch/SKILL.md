# Play Console 출시 플레이북

민트앤프렌즈(2026-11, 개인 개발자 계정)에서 실제로 통과한 답과 막혔던 곳을 정리했다.
새 프로젝트로 옮길 때는 이 폴더(`.claude/skills/play-console-launch/`)를 통째로 복사하고,
`profile_<앱>.json` 만 새로 쓴다. 사용자에게는 **콘솔 화면에 나오는 순서 그대로** 답을 준다
(순서가 다르면 사용자가 헷갈려 한다 — 실제로 지적받음).

## 0. 시작 전에 정해 둘 것
| 항목 | 기본값 / 메모 |
|---|---|
| 패키지명 | `io.github.<github아이디>.<앱>` — 개인 도메인이 없으면 GitHub Pages 주소 기준 |
| 기본 언어 | **English (United States) en-US**. 한국어 · 일본어 · 스페인어는 "번역 추가" |
| 웹 페이지 (GitHub Pages) | 소개 `/<앱>/` · 개인정보처리방침 `/<앱>/privacy/` · 계정 삭제 `/<앱>/privacy/#delete` · 이용약관 `/<앱>/terms/` · 루트 `app-ads.txt` (AdMob 쓰면 필수) |
| 문의 이메일 | 개발자 공개 이메일 (사용자 개인 메일 아님, 사용자에게 확인) |
| AAB 서명 | CI 에서 업로드 키로 서명 (비밀값 `ANDROID_UPLOAD_*`), versionCode = 1000 + run 번호 |

## 1. 앱 만들기
이름(30자) · 기본 언어 · **게임 / 앱** · **무료 / 유료** · 정책 · 미국 수출 법규 동의.

## 2. 앱 콘텐츠 (대시보드 → 앱 설정) — 화면 순서
| 화면 | 답 (게임 · 게스트 시작 · 광고 · 인앱 결제 기준) |
|---|---|
| 개인정보처리방침 | Pages 주소 |
| 앱 액세스 권한 | **모든 기능 제한 없이 사용 가능** (게스트로 시작하면 로그인 정보 불필요) |
| 광고 | **예, 광고 포함** (보상형 · 전면 · 배너 중 실제로 쓰는 것만 설명) |
| 콘텐츠 등급 (IARC) | 아래 2-1 |
| 타깃층 | **13세 이상**. 귀여운 그림체면 "어린이에게 관심을 끌 수 있음" → 예, 그리고 아동 대상 아님을 설명. 13세 미만을 넣으면 가족 정책 · 광고 제한이 붙는다 |
| 뉴스 앱 · 정부 앱 · 금융 기능 · 건강 · 코로나 | 모두 **아니요** |
| 데이터 보안 | 아래 2-2 (CSV 가져오기) |
| 광고 ID | **예, 광고 ID 사용** → 목적: 광고 또는 마케팅, 애널리틱스 (AdMob · Firebase Analytics). `AD_ID` 권한은 AdMob 플러그인이 넣는다 |
| 계정 삭제 | 앱 안 삭제 + 웹 주소 (`privacy/#delete`) |

### 2-1. IARC 설문
- 이메일 · 카테고리: **게임** (캐주얼/퍼즐)
- 폭력 · 공포 · 성적 내용 · 욕설 · 약물 · 술 · 담배 · 도박(실제 돈) · 모의 도박: 모두 **아니요**
- 사용자 간 상호작용 / 콘텐츠 공유: 친구 코드 · 정원 구경 같은 기능이 있으면 **예** (자유 채팅이 없다고 적기). 사용자가 이름을 직접 입력하면 **예**
- 위치 공유: 아니요
- 디지털 상품 구매: **예**
- 무작위 아이템(뽑기) 구매: **아니요** — 유료 무작위 상품을 만들지 않는다. "깜짝 상자"는 **사기 전에 내용을 보여 주고 고정**(D-039 방식)
- 기타 상호작용("사용자가 다른 사용자와 상호작용") 질문이 나오면 친구 기능을 그대로 설명하고, **신고 기능**과 친구 삭제를 함께 적는다 (UGC 정책상 신고 기능 필요)
- 결과 예상: 전체이용가 / PEGI 3 / ESRB Everyone (+ 사용자 상호작용 · 인앱 구매 표시)

### 2-2. 데이터 보안 — CSV 로 한 번에
1. 프로필 JSON 을 쓴다 (`profile_mintandfriends.json` 복사).
2. `python3 make_data_safety_csv.py profile_<앱>.json data_safety_import.csv`
3. 콘솔 → 데이터 보안 → **가져오기 · 내보내기 → CSV 가져오기** → 미리보기 확인 → 저장.

판단 기준 (Firebase + AdMob 앱):
- 게스트도 Firebase 익명 계정을 만든다 → **사용자 ID 필수 수집**.
- 계정 생성 방법은 **OAuth 하나만** (구글 · 카카오 로그인). 게스트 익명 계정은 고르지 않는다.
- **`PSL_HAS_OUTSIDE_APP_ACCOUNTS` · `PSL_INDEPENDENTLY_VALIDATED` 는 비운다** — OAuth 를 고르면 "답할 수 없습니다" 오류가 난다 (실제로 막혔던 곳).
- Firebase 처럼 **우리 대신 처리하는 서비스 제공업체로 보내는 건 '공유'가 아니다**. 공유 ✔ 는 AdMob(광고 네트워크)로 가는 항목만: 대략적 위치 · 진단 · 앱 상호작용 · 기기 ID.
- 임시 처리(ephemeral)는 전부 **아니요** (저장 · 분석함).
- 분석을 끌 수 없으면 앱 상호작용은 **필수**. 사용자가 직접 입력하는 이름만 **선택 가능**.
- 전송 암호화 예 (HTTPS · Firebase), 삭제 요청 가능 예.
- 앱마다 다르면 프로필의 `types` 만 바꾼다 (예: 크래시 리포트만 쓰면 `PSL_CRASH_LOGS` 추가, 위치 직접 쓰면 `PSL_PRECISE_LOCATION`). 질문 ID 는 `data_safety_template.csv` 2열에 다 있다.

| 스페인어 | **es-ES · es-US · es-419 세 개 모두** 같은 문구로 추가해도 된다 |

## 4. 인앱 상품 (수익 창출 → 제품) — 결제 프로필이 먼저
- **일회성 제품**: 소모성(다이아 팩) · 비소모성(1회 패키지) 모두 여기. 1회 패키지는 앱이 "계정당 1번"을 지키면 되고 콘솔 설정은 없다.
- **정기 결제**: 기본 요금제(월) 하나. 체험 · 할인 혜택은 처음엔 만들지 않는다.
- 상품 이미지(선택): **PNG 32비트, 1:1, 512~1080px, 글자 없음**. webp 아님.
- 상품 이름 · 설명은 언어별로 (`docs/store/PRODUCTS.md` 형식).
- ID 는 한 번 만들면 못 지운다 → 가격을 이름에 넣지 않거나 넣어도 바꾸지 않을 값으로.
- 인게임 할인(첫 구매 2배 등)은 **콘솔을 건드리지 않고** 앱 안에서 지급량으로 처리.
- 라이선스 테스트: 설정 → 라이선스 테스트에 테스터 Gmail → 실제 결제 없음.

## 5. 앱 서명 키 (첫 AAB 업로드 직후 꼭)
Play 가 **앱 서명 키**로 다시 서명하므로, 이 지문을 넣지 않으면 **Play 에서 받은 앱만 구글 · 카카오 로그인이 실패**한다.
1. 콘솔 → 설정 → 앱 무결성 → 앱 서명 → **앱 서명 키 인증서** SHA-1 · SHA-256 복사
2. Firebase → 프로젝트 설정 → Android 앱 → 디지털 지문 추가 (둘 다)
3. 카카오 키 해시: `python3 -c "import base64,sys;print(base64.b64encode(bytes.fromhex(sys.argv[1].replace(':',''))).decode())" <SHA1 콜론 포함>` (xxd 가 없는 환경이 많다) → Kakao Developers → 플랫폼 → Android 에 **Play 키 해시 + 테스트 APK 키 해시** 둘 다. 업로드 키는 필요 없음.
4. 카카오 네이티브 앱 키는 저장소 문서에 적지 않는다 (GitHub 비밀값만). 키를 바꾸면 AAB 를 다시 빌드.

## 6. AdMob
앱 추가(미게시 앱) → 광고 단위(보상형 · 전면) → 앱 ID · 단위 ID 를 GitHub 비밀값으로.
`app-ads.txt` 를 개발자 웹사이트 루트에 (`google.com, pub-XXXX, DIRECT, f08c47fec0942fa0`),
스토어 등록정보의 웹사이트 주소가 그 도메인이어야 한다. GDPR 메시지(개인정보 · 메시지)도 만들기.

## 7. 테스트 트랙 · 프로덕션
- 내부 테스트로 먼저 설치 확인 → **비공개 테스트**: 개인 계정은 **테스터 12명 이상이 14일 연속 참여**해야 프로덕션 신청 가능.
- 테스터 목록(이메일 · Google 그룹) → 승인되면 "웹에서 참여" 링크 공유.
- 14일 동안 볼 지표: D1 · D7, 튜토리얼 완료, 첫 구역 완료, 크래시 · ANR, 결제 퍼널(`shop_open → iap_begin → purchase`).
- 프로덕션 신청 설문: 테스트 방식 · 받은 피드백 · 고친 것 · 출시 준비 이유를 구체적으로.

## 8. Firebase 쪽 (같이 해야 하는 것)
- Analytics 맞춤 정의: 이벤트 매개변수마다 **맞춤 측정기준(범위: 이벤트)** 등록해야 보고서에서 나눠 볼 수 있다.
- Remote Config: 앱의 기본값과 **같은 값**으로 키를 먼저 게시.
- Firestore 규칙: 신고(`reports`)는 만들기만, 필드 검증.

## 쓸 때 주의
- 사용자 이메일 · 실명 · 비밀키를 문서에 쓰지 않는다.
- 답을 줄 때는 이 파일의 표를 **그 앱 사실에 맞는지** 먼저 확인한다 (광고 종류, 로그인 방법, 채팅 유무, 무작위 상품 유무).
