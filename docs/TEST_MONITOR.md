# 비공개 테스트 모니터링 (14일)

매주 한 번 (3일 · 7일 · 14일째) 아래 숫자를 가져오면 시뮬레이터 예측과 비교해 조정안을 낸다.
테스터가 적으므로 비율보다 **사람별 이야기**(누가 어디서 멈췄나)를 함께 본다.

## 어디서 보나
- **Firebase 콘솔 → Analytics → 이벤트**: 아래 이벤트 수 · 사용자 수
- **Analytics → 리텐션**: 1일 · 7일 재방문
- **Crashlytics**: 비정상 종료 · 오류 (1.0.6 부터)
- **Play Console → 품질 → Android vitals**: ANR · 비정상 종료율
- 게임 안 **개발자 모드 성장 로그** (설정 → 버전 7번 탭): 테스터 한 명의 하루 흐름

## 볼 지표와 기준

| 지표 | 이벤트 / 위치 | 시뮬 예측 (무과금 열심) | 이상 신호 → 할 일 |
|---|---|---|---|
| 1일 재방문 | 리텐션 | — | 30% 미만 → 첫 30분(튜토리얼 · 첫 구역) 점검 |
| 7일 재방문 | 리텐션 | — | 10% 미만 → 중반 막힘 구간 찾기 |
| 레벨 진행 | `level_up` | 7일 ≈ Lv20대 | 예측보다 많이 느림 → 별 · 에너지 공급 |
| 구역 완성 | `area_complete` | 2구역 ≈ 2일, 6구역 ≈ 69일 | 2구역이 4일 넘음 → 구역 별 값 |
| 하루 부탁 한도 소진 | `orders_done` (orders · hour) | 하루 4번 접속 시 오후 | 오전에 다 씀이 많음 → 원격 설정 `order_quota_per_friend` 4→5 (1.0.6 부터) |
| 에너지 바닥 | `energy_empty` | 세션당 1~2번 | 너무 잦음 → 충전 시간 · 광고 에너지 |
| 광고 시청 | `ad_reward` (kind) | 하루 3~6번 | 특정 종류만 0 → 버튼 위치 · 보상 매력 |
| 광고 못 봄 | `ad_unavailable` | 거의 0 | 많음 → 광고 로드 · 지역 문제 |
| 다이아 소비처 | `gems_spend` (what) | 부스트 · 보관 칸 위주 | 다이아가 쌓이기만 함 → 쓸 곳 부족 |
| 결제 흐름 | `shop_open` → `iap_begin` → `iap_purchase` / `iap_cancel` · `iap_error` | — | error 가 있으면 코드 확인 |
| 공유 · 초대 | `share_open` → `share_done`, `invite_applied` | — | open 대비 done 이 낮음 → 공유 실패 · 동기 |
| 재단장 | `renew` (round · seeds) | 첫 재단장 ≈ 2주 | 너무 빠름/늦음 → 씨앗 공식 |
| 랜드마크 | `landmark` (area · lv) | 7일 Lv5 · 30일 Lv9 | 아무도 안 세움 → 위치 · 안내 |
| 비정상 종료 | Crashlytics · vitals | 0 | 1건이라도 → 바로 원인 (급하면 중간 빌드) |

## 테스터 불만 정리 양식
한 줄에 하나: `기기 · 버전(설정 화면) · 무엇을 하다 · 어떻게 됐나 · 기대한 것 · (스크린샷)`.
같은 문제를 여러 명이 말하면 사람 수를 적는다. 우선순위: 진행 막힘 > 돈 · 보상 손실 > 불편 > 취향.

## 업데이트 원칙
- 빌드는 모아서 (주 1회 정도), 급한 것(실행 불가 · 진행 막힘 · 결제 손실)만 바로.
- 경제 숫자는 가능하면 원격 설정(Remote Config)으로 먼저 바꿔 보고, 확정되면 코드에 반영.
